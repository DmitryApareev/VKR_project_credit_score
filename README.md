# Оценка кредитного риска заёмщиков (Россия и Казахстан)

Учебный / дипломный проект на Python: предобработка данных, инженерия признаков, обучение нескольких моделей машинного обучения и сравнение качества на двух наборах данных (условно Казахстан и Россия).

## Цель

Построить модели бинарной классификации для прогноза дефолта по кредиту (`target`: 1 — дефолт, 0 — нет), сравнить алгоритмы между собой и сопоставить результаты по двум странам (по отдельным файлам данных).

## Структура проекта

- `data/raw/incoming/` — мои исходные файлы (реестр КЗ и выгрузка РФ). Ожидаются имена `kazakhstan_credit_register_synthetic_3000.csv` и `client_data.csv`, либо те же файлы в `~/Downloads/`, либо пути в переменных `KZ_REGISTER_CSV` и `RU_CLIENT_CSV`.
- `data/raw/kazakhstan_credit.csv`, `data/raw/russia_credit.csv` — приведённые к одной схеме признаки + 30 000 строк** каждый (bootstrap с лёгким шумом по числам). При каждом запуске `main.py` я пересобираю их из входных CSV.
- `data/processed/` — таблицы после очистки и feature engineering.
- `src/` — модули: предобработка, признаки, обучение, оценка, визуализация, утилиты.
- `models/` — сохранённые модели (`joblib`), отдельные подпапки `kz/` и `ru/`.
- `results/` — метрики (CSV), таблицы сравнения, графики (PNG).
- `notebooks/` — ноутбуки для EDA, моделирования и сравнения стран.

## Как запустить

1. Создать виртуальное окружение (по желанию) и установить зависимости:

```bash
cd credit_scoring_diploma
pip install -r requirements.txt
```

2. Запустить полный сценарий:

```bash
python main.py
```

После выполнения появятся файлы в `data/processed/`, `models/kz`, `models/ru`, `results/tables`, `results/figures`, `results/metrics`.

3. Ноутбуки (рекомендуется запускать из корня проекта `credit_scoring_diploma`, чтобы пути к данным совпадали):

```bash
jupyter notebook notebooks/01_eda.ipynb
```

## Кратко о моделях

| Модель | Идея |
|--------|------|
| **Логистическая регрессия** | Линейная граница в пространстве признаков; интерпретируемые коэффициенты после масштабирования. |
| **Дерево решений** | Последовательные правила «если — то»; наглядно, но склонно к переобучению. |
| **Случайный лес** | Ансамбль деревьев; обычно стабильнее одного дерева. |
| **Gradient Boosting (sklearn)** | Последовательное исправление ошибок; сильный baseline без подключения XGBoost. |

Метрики в проекте: accuracy, precision, recall, F1, ROC-AUC; также строятся матрица ошибок и ROC-кривые.

## Примечание про данные

- В моей российской выгрузке (`client_data.csv`) мало уникальных анкет; после bootstrap до 30 000 строк деревья/лес могут давать очень высокое качество за счёт повторов — в дипломе я это формулирую как ограничение выборки.
- В казахстанском реестре `days_past_due` по сути дублирует `npl_90plus` (у нормальных кредитов DPD = 0, у дефолтных — высокий). Чтобы не было утечки целевой, я перемешиваю все значения DPD между строками: распределение DPD по выборке сохраняется, но связь конкретного DPD с дефолтом этой же заявки разрывается. В главе про данные я кратко объясняю этот шаг.
